# src/services/pipeline/CLAUDE.md

The live frame path between the pipe and the store; loaded when you work under `src/services/pipeline/` (the Worker itself is `src/workers/pipeline.worker.ts`). Process topology is in `docs/architecture.md`; the store's side is in `src/services/capture/CLAUDE.md`.

## Order of operations

- The Worker assigns ids and posts a released group's bytes to the store over its own `MessagePort` **before** it dissects anything (ADR 0038). A frame whose dissection throws must still reach disk.
- Rows travel with `bytesSent` and without their bytes, and are attached, never staged: an empty `rawBytes` must not be written as a frame. A Worker with no store port says `stored: false` on its flush.
- Never invent a renderer-side "bytes and row" versus "row only" choice. The writer answers one local question: does this id already have a slot?
- Nothing is transferred to the store; messages are copied. A flush's bytes reach the store as one columnar `FrameSlab` (`src/services/capture/frameSlab.ts`) and the window as one transferred slab cut by `PackedRows.ends`; a shard batch's bytes are one slab too, and a shard sends none back (#17). A renderer row's `rawBytes` is a view into its flush's slab, so anything that posts it copies first: a clone of a view sends its whole buffer (`replayBundleFor`, `scripts/pipeline/replay-bytes.ts`).
- A live frame's bytes are a view into the agent's batch, never a copy of their own (`receiveBatch`), and every hop past the window copies into its own slab. A dissector reads through the view's `byteOffset`; `scripts/pipeline/frame-views.ts` dissects every fixture frame from an odd offset inside junk and fails on any changed tree or row.
- A tracker keeping bytes past its frame still `.slice()`s them: a kept view holds a whole batch alive, and a view of a transferred buffer reads empty. A TLS tracker that kept a view once lost its client random and left live connections undecrypted. `scripts/pipeline/moved-bytes.ts` dissects every real capture twice, detaching after each frame, and fails on any changed tree; `scripts/pipeline/arrival.ts` detaches too.

## Stop and drain

- Stop waits for the Worker's `drain` and flushes the last rows before the store `finish` (`stopCaptureAndSeal` in `src/App.tsx`, `handlePauseCapture`). Two ports into one process have no ordering between them.
- `answerDrain` replies only after the store acks an empty `appendBytes` posted behind everything else on the Worker's port, bounded by `DRAIN_BARRIER_MS` (5000).
- Worker failures post `{type:'failure'}` and reach `pipeline.onFailure`, which is only `console.warn` (`src/hooks/useAgentConnection.ts`). Listen for them in drives: about 5% of live frames once failed to dissect unnoticed.

## Flow control and catch-up

- Bound every queue. `liveFlow.ts` stops releasing frames past 50,000 unanswered by the store; main sheds whole batches past 256 MB owed (`electron/pipeCredit.ts`). A link faster than the app falls behind into the agent's pcapng, which holds every frame, and the status bar says by how much. `scripts/pipeline/live-flow.ts`.
- `catchUp.ts` reads a hole back from the agent's file, asking main for a capture id and the agent's file name, never a path. A file frame is numbered by counting from its `capture_boundary`, and the count is checked against a live frame on each side of the hole. Where the check fails, mark the hole. `scripts/pipeline/catch-up.ts` holds the result to an uninterrupted run, frame for frame.
- Catch-up does not count from the start of the file to reach a hole: every frame passed on adds its EPB's length (`epbBytes`, no options, as the agent writes) to a per-file sum, and a catch-up with an anchor jumps there after reading the header (#17). The sum is right only for the agent's own layout, so a landing must start with the anchor's EPB and match it; a miss counts from the start and seeks no more that capture. The sums are kept in runs (`frameSizes.ts`): a gap the stream never fills (a clear, a few frames the agent's queue shed) is counted across by the read, never guessed across, so it cannot switch the seek off. A clear while catching up calls `router.clear()`, not `reset()`: the files and where they were read go on. A shed notice for frames the file already delivered is clipped, not marked: a fast file can level before main's next notice arrives.
- Two adapters' skew can leave a number below `expectedSeq` that never came, because the shed batch held it: `… 5998, 6000` delivered, `5999, 6001, …` shed. `LiveFlow` remembers skew gaps for `LATE_WINDOW` numbers, and a catch-up reads those late numbers back with the rest. The first copy to arrive, from the file or live, is used and the other dropped. With no catch-up they are marked (`noteLost`), however few (#18).
- With Multi Threaded Capture on `auto` or above 1, the Worker is a coordinator (`coordinator.ts`): the one `Sequencer` numbers every frame, plain TCP segments go to shard Workers by connection (`shard.ts`, `src/workers/shardRole.ts`), everything else is dissected on the coordinator, and results merge back in id order. `1` is the single Worker exactly as before. `scripts/pipeline/parallel.ts` holds both to one output (ADR 0053).
- A shard is the same script started by its own URL; its trees stay in its cache and a click on a recent one is asked of it.
- A shard annotates its rows (`annotatePacket`, `markLiveGap`, on the socket table broadcast to the shards in order) and sends them as a `RowPack`, the chunk codec's own bytes (`rowPack.ts`). The coordinator runs fingerprints and network facts in merged order from each row's `RowSide` (`rowSteps.ts`) and writes what it adds as a `RowOverlay`. It decodes a pack only with more than one interface or for a `needsRow` row. The window and the store get the pack copied; only the window's bytes slab is transferred. `scripts/pipeline/row-steps.ts` and `parallel.ts` hold this to the single Worker (ADR 0053 phase 6).
- The window's `PackReader` splits as it decodes: dense fields go into a `FieldBlock`, never a bag, and `applyOverlay` puts a dense key (`tls.stream` settles at the merge) in the column, because a bag copy is shadowed by the column. A merge write to a dense key that bypassed `applyOverlay` would read stale. `scripts/pipeline/row-pack.ts` (#16).

## Revisit

- A frame's tree is not a function of its own bytes. A `FrameRecorder` writes every tracker answer at arrival and a `FrameRevisit` hands them back (ADR 0049). Dissectors reach tracker state only through `src/services/dissect/trackerApi.ts`, and outside facts (clock, HTTP/1 body budget, direction) through `src/services/dissect/dissectEnv.ts`.
- A record never holds a key or plaintext. Plaintext answers live in the Worker's memory-only `derivedStore.ts` and are emptied with the key log. A miss throws `RecordMiss` and falls back to `replay.ts`.
- `scripts/pipeline/revisit.ts` revisits every fixture frame and fails on a wrong tree; `scripts/electron/live-revisit-drive.ts` does it on a live capture through the installed agent. Run the drive after anything on this path.
